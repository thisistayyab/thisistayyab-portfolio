# Tayyab Portfolio (Next.js)

Production portfolio for [thisistayyab.dev](https://thisistayyab.dev) — static pages plus a **file-based blog**. No database, no CMS, no auth surface.

## Local development

```bash
npm install
cp vercel.env.example .env.local
# Fill in EmailJS values (see vercel.env.example)
npm run dev
```

Open [http://localhost:3000](http://localhost:3000).

- Blog: `/blog`

## Blog content

Posts live in this repo as typed TypeScript/React modules:

- **Bodies:** `lib/blog/content/<slug>.tsx` (registered in `lib/blog/content/index.ts`)
- **Metadata** (title, dates, cover image, SEO fields, tags, structured FAQ): `lib/blog/posts.ts`

Publishing a post is a commit and a deploy. Add the article body component in `lib/blog/content/<slug>.tsx`, register it in `lib/blog/content/index.ts`, and add its metadata entry in `lib/blog/posts.ts`. Build-time validation fails if any entry in `BLOG_POSTS` is missing a matching body component. To retire a post, remove both and add a permanent redirect in `next.config.ts` so the old URL keeps its ranking signal instead of soft-404ing.

## Deploy on Vercel

1. Push this repo to GitHub and [import the project on Vercel](https://vercel.com/new).
2. **Framework preset:** Next.js (auto-detected; `vercel.json` is included).
3. **Environment variables:** add every key from [`vercel.env.example`](./vercel.env.example) under **Project → Settings → Environment Variables** (Production + Preview at minimum).
4. **Domain:** attach `thisistayyab.dev` in **Project → Settings → Domains** (DNS as Vercel instructs).
5. Deploy. `/sitemap.xml`, `/robots.txt`, and `/feed.xml` are generated by the App Router (`app/sitemap.ts`, `app/robots.ts`, `app/feed.xml/route.ts`).
6. **Search indexing:** add verification env vars from [`docs/WEBMASTER.md`](./docs/WEBMASTER.md), then submit the sitemap in Google Search Console and Bing Webmaster Tools.

### After deploy

- Submit `https://thisistayyab.dev/sitemap.xml` in [Google Search Console](https://search.google.com/search-console).
- Blog pages are prerendered at build time; publishing a post is a commit and a deploy.
- **Vercel Analytics:** enable **Analytics** (and optionally **Speed Insights**) under [Project → Analytics](https://vercel.com/docs/analytics) in the Vercel dashboard. The app includes `@vercel/analytics` and `@vercel/speed-insights` in `app/layout.tsx` — no env vars required on Vercel.
- **Google Analytics 4:** set `NEXT_PUBLIC_GA_MEASUREMENT_ID` (see `vercel.env.example`). Loaded via `@next/third-parties/google` when the ID is present.

## Images

- Portfolio photos and project shots are served as **AVIF + WebP** pairs under `public/images/` for fast loads and SEO.
- Hero / Open Graph portrait: `public/images/about.avif` + `about.webp` (stylized cutout — do not overwrite from `about.jpg` without intent).
- **Crawler/share URLs** (`lib/image.ts` `imageSeoUrl`) never emit AVIF — X/Twitter, LinkedIn, Slack, iMessage, and Mastodon cannot read AVIF share images. They map to `.jpg` for assets with a JPG sibling (`og`, `projects/relay`, `projects/youtube-downloader`) and `.webp` for everything else. When adding a project image, either ship a `.jpg` sibling at the **same dimensions** as the AVIF/WebP pair (regenerate with `ffmpeg -i x.webp -frames:v 1 -q:v 3 x.jpg`) or extend `JPG_SIBLINGS` in `lib/image.ts` only after generating one.
- Unused / alternate files: `public/assets-archive/` (see `index.html`, `noindex` listing page; image URLs remain reachable).
